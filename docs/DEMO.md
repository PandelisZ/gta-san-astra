# GTA San Astra: two-minute demo

**Opening:** “Astra built this controller, and now Astra is the driver. Its only sensor is the game screen. We choose how many frames it gets before it has to decide again.”

The presentation below targets two minutes. Inference time varies; use a short bounded run and show recorded evidence if the live call takes longer. Do not describe a prepared video or a manual input as an autonomous result.

## Prepare before presenting

The current validated path includes capture, frame stepping, Astra vision, and a BIOS menu loop. San Andreas has booted; the stationary-car snapshot and autonomous-driving result remain to be established. Run the driving portion only after the starting scenario is captured and visually checked.

```sh
sh scripts/bootstrap.sh
GAME_ISO="/absolute/path/to/San Andreas.iso"
# PCSX2 must be stopped before this command.
uv run python scripts/setup_emulator.py --iso "$GAME_ISO" --launch
uv run san-astra doctor
```

Position the car on an uncomplicated road and stop it. Pause **emulation** with Space while PCSX2 has focus; Start opens the game's own menu. Capture the scenario:

```sh
uv run python scripts/scenario.py capture stationary-car --iso "$GAME_ISO"
```

The scenario includes `.runtime/scenarios/stationary-car/frame.png`, `state.p2s`, and `manifest.json`. Check the screenshot before calling it a driving start. Reuse the same state between attempts. Quit PCSX2, then restore it:

```sh
uv run python scripts/scenario.py launch stationary-car --iso "$GAME_ISO"
uv run san-astra observe
```

Keep the emulator and terminal/report side by side. Keep the window visible, with no dialog covering it. Default capture removes its titlebar; fullscreen requires `SAN_ASTRA_CROP_TOP=0`.

| 1:30–2:00 | The evidence report and source | Show input, before/after screenshots, latency, and requested frame counts. Explain what was built with Astra and which driving outcomes still need evaluation. |

Run a short live attempt from the restored scene:

```sh
RUN_DIR="runs/judge-demo-$(date +%Y%m%d-%H%M%S)"
uv run python scripts/autodrive.py \
  --model gpt-6-astra --steps 4 --frame-stride 10 \
  --goal "Follow the road ahead and avoid collisions. Stop if the view is unsafe or unclear." \
  --scenario-state .runtime/scenarios/stationary-car/state.p2s \
  --run-dir "$RUN_DIR"
uv run python scripts/report.py "$RUN_DIR"
open "$RUN_DIR/report.html"
```

`--scenario-state` records the initial state's identity; it does not load it. The prior `scenario.py launch ... --iso ...` command performs the reset. Four decisions are a short integration demonstration, not a driving benchmark.

If the starting vehicle scenario is not ready, show the [recorded vision/menu evidence](EVIDENCE.md) and label the driving demo incomplete. If input needs to stop, press Ctrl-C and run:

```sh
uv run san-astra release
```

## Answer the frame-rate question precisely

A stride of 1, 5, or 10 means the bridge requests that many emulated VSyncs between observations. At NTSC 59.94, the nominal observation cadence is 59.94, 11.99, or 5.99 observations **per game second**. It is not wall-clock model FPS. The emulator pauses while Astra decides, screenshots may repeat, and no internal telemetry is read to certify individual frame delivery.

For menu buttons, put an empty step between repeated presses so the game samples the release:

```sh
uv run san-astra step --frames 5 --buttons cross
uv run san-astra step --frames 5
uv run san-astra step --frames 5 --buttons cross
```

Those are manual diagnostic commands. Autonomous runs make their own decisions. Driving actions can keep controls held across successive steps without a neutral gap.

## Connect to the judging criteria

- **25% Astra development:** primary Astra agent plus three focused subagents implemented and tested the native bridge, Python/MCP controls, and visual decision runner. Show the Git history and a relevant failure fix.
- **25% Astra in the project:** the live decision is generated by `gpt-6-astra` from screenshots, then schema-validated before input.
- **25% live demo:** show the loop and its actual outcome. Preserve a failure in the evidence instead of substituting a success claim.
- **25% technicality:** explain paused stepping, the menu release-sampling edge case, input locking/cleanup, scenario integrity, and the distinction between requested frames and measured game state.

**Close:** “The experiment is inspectable: the same starting scene, a chosen observation cadence, and a record of what Astra saw and pressed. Driving quality comes from the evidence.”
